# Decisions

One line per decision that is hard to reverse, with the reason. The linked doc holds the detail;
load it before changing that area.

| Topic           | Decision                                                                                                                                                                                                                                                                                                  | Why                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Role            | One account for the whole suite (YAN-184). The other apps sign in through this one and keep their own session and database. No households yet.                                                                                                                                                            | One sign-in flow means a fix lands once.                                                                     |
| Auth library    | Better Auth 1.7.23, pinned exactly, with the Prisma adapter. → [docs/sign-in.md](docs/sign-in.md)                                                                                                                                                                                                         | Sessions, email codes, Google and an OIDC provider in one maintained library, on the suite's Postgres.       |
| Protocol        | OpenID Connect provider (`@better-auth/oauth-provider`): authorization code with PKCE S256, confidential clients, `client_secret_basic`. Issuer `<origin>/api/auth`; EdDSA id_tokens carrying `email` and `email_verified`. → [docs/clients.md](docs/clients.md)                                          | A standard any app can verify with a JWKS, no shared secret per session.                                     |
| Trusted clients | Suite apps are created by `scripts/create-client.mts` with `skip_consent`, never over HTTP: every client-management route is disabled. `skip_consent` on the client row alone decides consent; `TRUSTED_CLIENT_IDS` only caches them and freezes them against edits. → [docs/clients.md](docs/clients.md) | The family's own apps must not ask permission; a stranger must not be able to register one.                  |
| Sign-in         | Passwordless: a 6-digit emailed code (stored hashed, 10 minutes, 5 tries), or Google when configured. No magic link. → [docs/sign-in.md](docs/sign-in.md)                                                                                                                                                 | A code works in a home-screen app, which keeps its own cookies; a link would sign in the mail app's browser. |
| ORM             | Prisma 6.19.3, like the other apps; the schema is generated by the Better Auth CLI. `vercel.json` migrates before every build. → [docs/deployment.md](docs/deployment.md)                                                                                                                                 | Better Auth's Prisma adapter works with 6; moving to 7 is a suite-wide change, not this app's.               |
| Cost fences     | Better Auth's rate limit in the database on the code routes only; sign-in mail behind `app-kit`'s daily budget in Upstash, checked before a code is made.                                                                                                                                                 | Each code costs a mail from a quota shared by every sign-in.                                                 |
| UI              | `@yaniv120892/my-ui` for theme, he/en and RTL. The card copies `AuthCard`'s layout with its own mark, since my-ui's `APP_IDS` has no accounts entry.                                                                                                                                                      | Same look as the apps that send people here.                                                                 |
